# Resume and Academic CV — evidence-based tailoring

Read this when the user asks to write, compress, tailor, edit, assess or format a resume/CV.

## Audience and organizing principle

Communicate **Information (skills and qualifications) → Purpose (reach the next interview/admissions review) → Audience (HR plus technical/business evaluators)**. Every major entry should let the reader detect: **Impact, Relevance, Personal Contribution**. Do not mistake describing duties for demonstrating an ability. Content is selected by target criteria, not by what sounds most prestigious.

## Intake and targeting

- Read the actual JD/admissions call, current resume/CV, original experience notes, Evidence Bank, permitted supporting sources, and target layout/page constraints.
- Extract the **3–5 highest-priority role capabilities** and all hard eligibility requirements.
- Sort each factually supported experience into directly relevant, transferable, or not relevant. Reorder, shorten or exclude accordingly; never use one unmodified resume for every role.
- Include only coursework, tools and skills that support the application. A technology name without evidence is insufficient.

## Writing bullets that prove fit

Build each bullet as **accurate action verb → what I specifically contributed → completed output / result → demonstrated role-relevant capability** (the last link can be implicit when obvious). Concrete output matters more than a chronological duty list. Use accurate verbs such as Designed, Built, Evaluated, Coordinated, Improved when they genuinely describe the applicant's work; avoid inflated "led", "owned", "deployed" or "invented" claims.

- Quantitative metrics require a source. Do not manufacture "increased accuracy 15%" or user/revenue counts.
- When there is no numeric measure, describe the true scope, artifact, test, prototype, demonstration, analysis or documented decision.
- Keep applicant actions separate from team activities and future plans. Preserve "ongoing" if ongoing; an intended experiment is not completed research and an under-review submission is not a published article.
- Trim filler adjectives, clichés, chains of buzzwords and irrelevant technical minutiae. Do not repeat the same output across many bullets without a different relevant point.
- For product, operations or cross-functional roles, select evidence of analysis, constraints, execution, communication and decisions — not only software implementation details.

## Resume versus Academic CV

**Resume**:
- Default to **one page for a current university student**. One to two pages can be reasonable if justified by experience or recipient rules; mandatory external page limits override preferences.
- Use legible contact header, Education, relevant Experience/Research, Selected Projects, Skills, Awards (only if true) and other relevant sections. Omit weak/empty sections.
- Standard readable headings, consistent dates/tense, short accomplishment-driven bullets and ATS-compatible structure. Avoid charts, elaborate graphics and decorative tables in an ATS version unless requested.
- A good recruiter-oriented resume can be terse and heavily tailored; it is not an exhaustive autobiography.

**Academic CV**:
- More comprehensive record when appropriate: Education, Research, Teaching, Presentations, Projects, Skills, Publications (only genuine ones), Awards, selected service and methods as relevant.
- Use the required format/length or sensible discipline-appropriate scope; an academic CV may exceed one page, but not indefinitely or to pad entries.
- Distinguish published, accepted, submitted/under review and works in progress using accurate labels only if official requirements permit and evidence exists. Do not create a "Publications" section solely to fill space.

## Checks before output

Verify person, institution, degree, GPA (including scale and effective date where necessary), job titles, dates, project completion, organization name, personal-vs-team scope, all numbers, English proficiency/testing, eligibility claims, spelling, ATS readability, tense and format. Do not copy **any** fictitious sample employer, university, example award, invented internship, publication or placeholder credential from a resume template.

## Delivery

Normally return (1) a short role-positioning rationale, (2) the requested complete resume/CV **or** replacement bullets/sections, and (3) significant changes plus unresolved evidence. If asked for one revised bullet, output that and nothing more. If LaTeX is requested, read [format-and-templates.md](format-and-templates.md), preserve the selected style, replace all sample data, and inspect compile/output when tools permit.
