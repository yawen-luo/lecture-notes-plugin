# Evidence Bank, opportunity verification, and application source discipline

Read for every Career Application task. Treat the applicant's original, up-to-date evidence as the data source; the skill defines a method, not an applicant profile.

## Required input and confirmation

Collect or locate only what this request needs:
- Target employer/lab/university, exact role/program, Req ID (if any), and official job description or admissions instructions.
- Applicant's latest resume/CV and verified Education, Experience, Projects, Teaching, Skills, Awards and Publications.
- The user's privately held Evidence Bank, project records, transcript, portfolio and original references if accessible.
- Any official/user-provided rubric, required output format, length, tone, and submission channel.

For a **new role-specific cover letter**, request the missing JD instead of fabricating a generic one. If the user wants a generic resume without a JD, produce a clearly untargeted version without pretending to have matched a role. If the user specifically requests only a quick rewrite, perform the constrained edit without collecting an entire application dossier.

## Fact provenance hierarchy

1. Applicant-confirmed primary documents or original transcripts/project records, with current verification.
2. Fetched primary official source (e.g., university/program site, employer posting, repository contribution history), when relevant and accessible.
3. Current private Notion fact index with inspectable source references — verify individual claims before submission.
4. Historical ChatGPT conversations or old drafts for leads and preferences only.
5. Templates and generic examples — **never** factual applicant evidence.

Never treat the word "verified" on an older note as a guarantee that a time-sensitive fact remains current. Never quietly upgrade the status of an uncertain claim.

## Minimal evidence record

For each potentially reusable experience track:

| Field | Meaning |
| --- | --- |
| What | Exact project, appointment, competition, course, or research activity |
| My Role | Actual personal function; individual vs team scope |
| Actions | Specific tasks the applicant truly performed |
| Outcomes | Completed output, evaluation, measured result or other evidence |
| Evidence | Source file, date, link, author/contribution record or applicant confirmation |
| Date | Actual start/end, current, or planned status |
| Status | Completed / ongoing / planned / unclear; publication and deployment separate |
| Target Roles | Jobs/programs for which this experience could be relevant |

For a document-specific mapping, use:

Requirement → My verified example → My specific action → Result or inspectable output → Relevant capability/value.

Label each mapping **direct**, **transferable**, or **not relevant**. Exclude decorative, forced connections. A course syllabus is not a completed external project; a hackathon is not employment; "under review" is not "published"; a demo is not a launched product. A team deliverable does not prove sole ownership.

## Opportunity verification, when the task includes evaluating or locating a live opening

Check the original organization/program application page, not just search snippets, unofficial aggregators, or cached dates. Record:

- Official URL and check date.
- Exact name, requisition/program ID, degree level and graduation-year eligibility.
- Current listing status, application-entry validity and acceptance of applications.
- Deadline with precise date/time/time zone if officially stated; otherwise "not announced". Use "rolling" only if the source explicitly says so.
- On-site/hybrid/remote status; if international remote, whether work **from the applicant's country** is actually permitted; applicable hiring, time-zone and work-authorization restrictions.
- Hours, availability windows, duration, start date, compensation/funding and required documents when verified.
- Eligible vs uncertain criteria, and any documented reasons an opportunity is not open.

Do not describe an expired, offline or closed position as currently applyable. If the link works but the open status is unclear, mark **status unverified**, not "open". Lab interests alone do not establish a recruiting vacancy. Distinguish visiting-student arrangements, paid research assistantships and conventional internships. Do not imply funding where none is specified.

## Personal-data and consistency checklist

Independently verify the precise degree title, institutional English spelling, graduation year, GPA/scale/date, language-test date and validity, position titles, appointment dates, scope, leadership role, experiment details, publications, acceptance and numeric outcomes. On first mention use official institutional English names where helpful; for Shanghai Jiao Tong University the official transliteration is "Jiao Tong", not "Jiaotong". Use a familiar abbreviation afterwards if it improves readability. Do not require credentials irrelevant to the role.

If in doubt, maintain a **facts needing confirmation** section outside the finalized application document. Never plant "[UNVERIFIED]" or an invented placeholder in a purported submission-ready version without clearly indicating it is a draft.
